# Reader Feedback

Record feedback while reading the learning chapters. Anchor the concern to a section or stable claim link whenever possible. The primary agent should disposition each entry visibly rather than silently rewriting around it.

| Date | Artifact or section | Reader concern | Type | Disposition | Resolution |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

## Types

- `unclear`
- `unsupported`
- `missing`
- `counterexample`
- `impractical`
- `confusing terminology`
- `desired depth`

## Dispositions

- `fix now`
- `targeted research`
- `next cycle`
- `open`
- `rejected with reason`

## Review questions for the first chapter

1. Did the chapter materially improve your understanding of harness control?
2. Was the progression from model action to programmed boundaries intuitive?
3. Were runtime integrity, task acceptance, and external evaluation clearly distinct?
4. Did any optional capability read as though it were a default?
5. Did uncertainty remain visible without interrupting the learning flow?
6. Were the implementation comparisons deep enough to be useful?
7. Could you reach the evidence when you wanted it without being forced into it?
8. What felt unsupported, confusing, shallow, or missing?
9. Which topic should receive deeper research next?
