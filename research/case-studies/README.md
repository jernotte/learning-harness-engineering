# Case Studies

This directory holds deep analysis of implementations and techniques. Case studies should trace mechanisms and evidence, not repeat product documentation. Start with `../templates/case-study.md`, then adapt the presentation to the subject without losing the distinctions required for comparison.

A case study may remain provisional or incomplete. Its maturity and unresolved questions should say so plainly.

Case-specific responsibility friction also enters the cumulative [Taxonomy Friction Register](../TAXONOMY-FRICTION.md), where later implementations can confirm, qualify, or contradict it before Checkpoint 3.
